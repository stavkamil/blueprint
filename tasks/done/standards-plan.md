## Overview

Write blueprint's agent-agnostic coding standards and ship them in the npm package:

- **Five judgment guides** in `standards/`: `typescript.md`, `testing.md`, `structure.md`, `workflow.md`, `react.md`
- **The AGENTS.md block** `standards/agents-block.md`: pointers plus "Done means"
- **A content test suite** that keeps the guides short, positive, single-sourced, and their examples correct

Blueprint's own `AGENTS.md` starts using the standards too, so they're tested on blueprint before any project gets them.

## Architecture decisions

1. **Criterion 3 is split across modules:**
   - **Now:** every `ts`/`tsx` example declares its path (`title="…"`), and every `ts` example **typechecks** under blueprint's strict tsconfig in a temp folder.
   - **In `config-presets`:** every example is **linted** with the real presets at its path, and the `tsx` (React) examples are typechecked in the nextjs fixture, which brings React's types. The spec is updated to say so.
2. **Content tests live in `tests/standards.spec.ts`,** next to `tests/` rather than `src/`, since they test repo content, not product code. They run in `pnpm test`, and coverage still measures `src/` only.
3. **Test-driven, one guide per task.** The test keeps a list of required guides. Each guide task first adds its name to that list (the test goes red), then writes the guide until it's green.
4. **Rule-placement check:** the test holds a small keyword map from each guide-catalog rule to the one guide it belongs in. It fails if a rule is missing, or if its key phrase shows up in a second guide (criterion 6).
5. **"No negative examples" check:**
   - no ❌ markers
   - no example headings like "Bad", "Wrong", "Don't"
   - no code block marked as a counter-example
6. **Dev dependency `zod`,** so the `typescript.md` examples that validate data typecheck for real. It's needed for testing only; blueprint ships no runtime dependency.

## Risks and mitigations

| Risk                                                        | Impact | Mitigation                                                                                            |
| ----------------------------------------------------------- | ------ | ----------------------------------------------------------------------------------------------------- |
| Guides drift into restating lint rules or growing long      | Med    | The content test enforces length, single placement and positivity; the spec's catalogs are the source |
| The "no negative examples" check is too strict or too loose | Low    | It checks explicit markers and headings only; anything subtler is judged in your PR review            |
| `zod` example types change with a zod major                 | Low    | `zod` is a dev dependency, updated by the weekly Dependabot PR, and the test catches breakage         |
| The guides read well but agents ignore them                 | Med    | That's what criterion 7's agent check is for (after `project-template`); the pruning pass follows     |
